## Non-outlined decisions

- Use plain Vite/React with TanStack Router and Query, rather than a TanStack Start server runtime. Existing application pages are client-driven, and public SEO shells are generated at build time.
- Remove the connected-app `/connect` flow, settings panel, and `connect.clashk.ing` routing after coordinated confirmation that the API has no implementation or replacement for the five shared-grant/application endpoints. No replacement feature was invented.
- Remove the dead `/admin/creators` page and navigation after coordinated API/schema confirmation that its GET/PATCH creator-application endpoints and storage do not exist.
- Move Tenor resolution to the typed API-owned POST endpoint; remove the Dashboard's local route and server helper.
- Keep Discord resource ownership in the authoritative schema repository. Record only resources actually created by a feature, never backfill arbitrary existing IDs, and preserve resources when ownership or safe deletion cannot be proven. Resource cleanup requires the shared writer-lock and reference-check protocol, not merely a configuration row containing an ID.
- The six former QUERY endpoints have no current Dashboard source callers. Shared-contract regression checks require POST with a JSON body; no unused callers were added.
- A cloned roster starts with no Discord webhook/message pair. The PostgreSQL fixture exposed that copying the source pair violates its unique index; the clone now leaves those fields null while preserving the source.
- Canonical roster refresh keeps the configured 15-minute cooldown, fences refresh completion by its claim timestamp, and applies player results only to the row version observed before the lookup. This preserves a new signup or edit when an older lookup returns later; only an authoritative Clash 404 removes a player.
- AI authorization and settlement share the schema-owned permanent `roster_ai_budget_locks` row from migration 023. Exact settlement retries return 204, while conflicting retries return 409; the preserved zero-cost admission policy is not an in-flight spend reservation.
- Mobile bookmark and recent-search writes use the schema-owned per-subject row mutex from migration 013. This preserves bot operations for subjects without an authentication account, without creating fake users or taking a global table lock; authenticated writes also lock and recheck the real account row.
- Use the API-owned R2 `clashking-media` bucket for base and giveaway uploads and `clashking-ticketing` for ticket artifacts. Public media URLs use `/v2/media/:filename`; do not add a legacy Bunny fallback. Dashboard upload consumers preserve the API-returned URL without rewriting its origin. Unknown Discord or database commit outcomes retain created resources for reconciliation rather than claiming a failed write or automatically deleting a possibly referenced resource. Full cleanup parity remains a separate release gate.
